RabbitHole security review

Full codebase · 25 source files, manifest, fixtures and capture script · 28 August 2026

Bottom line: safe, and now safer. No high or critical issues were found. The two low findings below were fixed on 28 August 2026, with tests. One thing remains worth knowing.

Fixed

FixedFetched URLs were trusted as-is

The extension fetched thread content from a URL it read off the GitHub page, without checking where that URL pointed. Today only GitHub writes that attribute, so this was hardening rather than a live hole.

Fix applied: the fetch transport now refuses any URL that is not the page's own path or an absolute URL on the page's own origin. A refused URL reads as a failed fetch, so the row says the thread could not be read. Guard and rationale in src/fetch/threads.ts, four new tests.

Fixed"Copy agent prompt" trusted anyone

The prompt was read from any comment containing a "Prompt for AI Agents" block, not just CodeRabbit's. A hostile PR commenter could plant a fake prompt that a reader copies straight into their coding agent.

Fix applied: the prompt is only read when the comment's single author link is exactly CodeRabbit's account. Anyone else's block yields nothing, and the row already had words for that: "This comment carries no agent prompt." Gate in src/parse/authors.ts and src/parse/finding.ts, two new tests. No fixture count changed, so the gate cuts nothing real.

Worth knowing

InfoTest fixtures keep some GitHub identifiers

All session tokens in the committed fixtures are verified redacted (the capture script refuses to save otherwise, which is good design). What remains are harmless analytics IDs and usernames. Fine for public repos, just be aware when capturing from work ones.

What is done right

  • Tiny permission surface. Only storage and contextMenus. No host permissions, no web-accessible resources.
  • No message passing. Components talk only through validated storage, so a whole class of extension bugs cannot exist here.
  • Untrusted HTML is parsed, never injected. No innerHTML anywhere. Fetched content goes through an inert parser and comes out as plain text.
  • Minimal page writes. The extension only ever toggles one CSS class and adds one stylesheet. Everything is reversible.
  • Exact identity checks. CodeRabbit is matched by account path, not display name, so impersonation fails.
  • One dependency. Just Preact. Supply-chain exposure is about as small as it gets.
